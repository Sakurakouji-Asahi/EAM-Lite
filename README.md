# EAM-Lite

EAM-Lite 是公司局域网内使用的轻量级企业资产管理系统。本仓库根目录就是包含
AGENTS.md、docs/、tasks/ 和 manage.py 的当前目录，不存在第二层项目仓库。

当前软件版本为 **v0.2.2-rc.1 试用版**，操作入口见 [试用指南](docs/Trial-Guide.md)。实现沿用 **Requirements V1.1** 和 **V1.2 低值物品扩展** 的历史设计。原需求由 AI 生成，不代表用户逐条确认；当前协作以 [AGENTS.md](AGENTS.md) 和 [文档定位](docs/README.md) 为准。
软件版本号与需求文档修订号相互独立：v0.2.1 表示 Sprint 0–18 功能基线完成生产加固、
库存核算不变量和小型制造企业易用性整合后的候选版本，Requirements
V1.1/V1.2 表示对应业务需求修订。

v0.2.1 已累计整合 Sprint 0–18 的代码范围。现有功能包括身份与审计、
基础资料、导入、资产编码与主档、财务确认与折旧、二维码标签、调拨借用与处置、盘点、
保养、离职清退、Dashboard、固定报表、T+ 人工对账导出，以及公司内部数量型低值物品的
库存、保管、盘点、清退和正式报表。T+ 仍是正式会计系统；本应用
不调用 T+ API、不写 T+ 数据库，也不自动入账。

仓库已包含 Gunicorn 26.1.0、Caddy 2.11.4、PostgreSQL 18.6 Compose、生产 fail-closed 配置、加密数据库+附件
备份、30 日保留、system_admin 一次性下载授权和隔离恢复命令。已有恢复与上线核查结果见
[历史验收记录](docs/Sprint-12-UAT-Evidence.md)；本次文档整合未重测实际环境。真实 DNS、HTTPS、独立备份、
性能和岗位使用结果仍应由对应环境的证据确认，不能从软件版本或本文推断生产已验收。

`v0.1.0` Git 标签记录历史功能快照，不等于生产环境已完成验收。开发开始时先核对当前工作树和分支；2026-09-09 本目录位于 `codex/development`，不因旧文档切回历史开发分支。工作位置、文档性质和验证记录见 [开发入口](README-CODEX.md) 与 [文档索引](docs/README.md)。

## 本机工作方式

- 开发版在 `D:\资产管理`，使用 `启动开发环境.cmd`，默认地址 `http://127.0.0.1:8766`。
- 正式版目录为 `D:\资产管理-正式版`，本机稳定入口为 `启动EAM-Lite.cmd`，默认地址 `http://127.0.0.1:8765`。
- 手机开发验收使用 `启动开发环境-局域网扫码测试.cmd`，运行窗口给出当前局域网地址；真实业务多终端访问按部署环境配置。
- 两个目录的数据、附件、密钥和运行资源相互隔离。需要同步时按现有脚本的备份、干净工作树和来源校验步骤执行；详细步骤集中在 [本机使用说明](README-本机使用版.md)。

## 已有业务能力

| 模块 | 当前代码范围 |
|---|---|
| 基础平台 | 登录、角色和部门范围、公司及组织档案、初始化、受保护附件、审计 |
| 逐件资产 | 实物建档及编号、可后补照片、独立财务折旧确认、标签、调拨借还与历史记录 |
| 财务支持 | 会计认定、六类折旧方法、期间确认与冲销、Excel 对账支持 |
| 日常管理 | 资产盘点、预防性保养、员工离职清退、Dashboard 和报表 |
| 低值物品 | 独立数量域的档案、库存、领退调拨、保管、盘点、清退与报表 |

这些内容描述现有实现，不代表原 AI 需求全部经过用户确认。现有 Asset 数量为 1；数量型低值物品在独立 supplies 中，改变这种数据含义时需要评估历史兼容性。

## 日常操作中的近期调整

试用版的台账分别按创建日期和正式建档日期筛选；财务待办支持资产搜索、部门及资料状态筛选。批量建档可跨页选择最多 200 件，并为未建档草稿预览、统一补充部门、责任人和位置。详见 [试用指南](docs/Trial-Guide.md)。

资产台账支持批量核对与建档；租入归还按实际业务日期反映在历史报表，并同步处理保养计划。误登记可通过保留原记录的撤销流程更正，操作入口见 [批量建档与登记更正](docs/Asset-Registration-Corrections.md)。

2026-09-14 已按用户要求 [移除实物类型](docs/Remove-Physical-Type-2026-09-14.md)，包括数据库字段及日常维护入口。使用实际资产分类筛选报表，原分类、编号和历史导出保留。

2026-09-12 已更新开发版：LV 资产无需等财务即可进入逐件耐用品列表，Excel v3 模板支持新编码资料，日期回显统一，资产可按楼层筛选，人员可按部门、岗位和标记查找，页面复用单次请求的角色查询。2128 个唯一用例验证完成，原数据保留；备份及运行状态见 [本次改进记录](docs/Project-Improvements-2026-09-12.md)。

资产支持用户提供的 `AA-CC-YYYY-NNNNNN-SS` 编码：首次管理属性、实物类别、取得年份、流水号和子项号分别保存；财务认定改变不改编号或二维码。新增组件、组合成员版本、拆并来源、电子台账标识及租入资产归还入口，拆并金额由财务另行处理。操作见 [当前资产编码规则](docs/Asset-Coding-Standard.md)。

新资产无需等待财务复核，也不要求照片；建立后可以补拍。财务在发票等资料齐备后另行确认金额与折旧设置，已有编号和使用状态保持不变。详见 [本次业务变化](docs/Asset-Registration-and-Finance-2026-09-09.md)。

资产台账筛选后点击“报表与导出”，先核对筛选摘要和资产数量，再生成 Excel。“更多筛选”提供标签、保养、序列号、可见附件和建档日期等条件。历史日期及财务口径报表继续从报表中心进入。

新建和调拨表单支持部门与责任人联动；盘点草稿与发布确认页展示预计应盘数量及清单。对应修复与当时回归见 [9 月 7 日易用性修复记录](docs/Usability-Repair-2026-09-07.md)。

标签打印现在在生成 A4 预览时记录打印操作，无需再次“确认打印”；纸张实际贴好后，通过扫码或受保护的 Web 页面逐项确认。打印记录不等于已贴标。权限、当前二维码、责任资料和幂等均由后端校验；流程细节见 [开发指南](docs/Development-Guide.md) 和 [标签设计参考](docs/05-UI-UX.md)。
