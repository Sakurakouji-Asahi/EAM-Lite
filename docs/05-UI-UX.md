# EAM-Lite UI / UX 规范 V1.1

## 1. 总体原则

- 所有业务标签、帮助文字、校验错误和导出入口使用中文。
- PC 端用于初始化、资产主档、财务、报表、差异处理和系统设置；手机端重点支持扫码查看、盘点、贴标确认及保养完成。
- 使用 Bootstrap + HTMX + Django Templates，不引入不必要的 SPA。
- 页面显示权限、后端字段权限和导出权限必须一致；无权字段不进入 HTML 或接口响应。
- 操作按钮只在当前状态和权限同时允许时显示；即使按钮隐藏，后端仍必须拒绝非法请求。
- 所有受控状态动作采用明确的动作页/模态框，不允许在普通编辑表单中直接修改状态字段。
- 正式资产没有普通删除按钮。只有未提交、无业务引用的草稿在满足权限时显示“删除草稿”。
- 金额右对齐并使用千分位和两位小数；Excel 导出保持数值单元格。日期统一显示 `YYYY-MM-DD`。

## 3. 首次设置向导

向导固定为九步：

1. 公司；
2. 部门；
3. 人员；
4. 实物分类；
5. 位置；
6. 编码规则；
7. 折旧规则与财务参数；
8. 用户、角色及部门数据范围；
9. 校验并完成。

每一步均可保存并返回。第 9 步逐项显示通过/未通过及修复链接，至少校验：公司、一个启用部门、一名启用员工、一个实物分类、一棵包含具体位置的位置树、一个当前生效编码方案、系统折旧默认值、至少一名 `system_admin` 和一名 `finance`。

正式进入第 3 步前，首次 Django superuser 必须通过受控账号引导创建首批应用用户并分配固定角色，至少使 `system_admin`、`hr` 和 `finance` 角色能够登录完成各自步骤。账号引导只负责用户和角色，不让 `system_admin` 代行人员任职维护或财务确认。

点击“完成初始化”前显示最终摘要。完成只锁定初始化标记，不生成审批流程；后续修改走相应配置页并记录审计。

## 6. 新增与编辑资产

页面按四个分区显示。

### 6.1 基本资料

- 资产名称（必填）；
- 实物分类（必填，树形选择）；
- 品牌、型号、厂家；
- 序列号、出厂编号、历史编号；
- 数量（固定显示 1，只读）；
- 单位（必填）；
- 备注。

页面在数量旁固定提示：“V1 每条记录代表一件实物；相同多件请分别建档。”批量导入模板同样要求一件一行。

system_admin 在 draft/pending_finance 的技术设置区可选“指定编码方案版本（可空）”；其他角色只看到系统将使用“指定版本/分类默认/公司默认”的只读来源提示。正式发号后该选择锁定，页面以 `IssuedCode` 的实际方案版本为准。

### 6.2 使用信息

- 部门（必填）；
- 责任人（必填，按部门过滤且只允许在职员工）；
- 位置（必填，树形选择到具体位置）；
- 购置日期；
- 达到可使用状态日期；
- 是否需要保养。

“达到可使用状态日期”在使用信息和财务确认区显示的是同一个 `Asset.commissioning_date`；财务确认只能核对/修正这一字段，不得保存第二份同义日期。

正式资产页面中部门、责任人、位置显示为只读，并提供“调拨/变更”按钮；不得在普通编辑保存时覆盖。

### 6.3 照片与附件

- 封面照片；
- 资产照片；
- 发票、合同、验收单、说明书、合格证、其他。

提交财务确认前至少存在一张有效资产照片。上传区显示允许格式、当前配置上限（系统默认单文件 20 MB）、进度和失败原因。财务附件选项只对有权限用户显示。

### 6.4 财务信息

只对 `finance` 显示并可编辑，对 `management` 在正式资产详情只读显示。草稿创建页不要求普通业务角色填写。

- 会计认定；
- 固定资产类别；
- 原值（所有会计认定均必填，允许为 0，不得为空或为负数）；
- 入账日期；
- 达到可使用状态日期；
- 折旧方法、使用年限；
- 残值方式及残值率/金额；
- 折旧起始规则和日期；
- 正式编号生效日期（默认当前上海业务日，不得为未来；旧资产历史日期需原因）；
- 期初累计折旧、减值；
- T+ 资产卡片编码（Sprint 11 建立 AssetExternalReference 后才显示；可空，仅人工对账，不触发写入；Sprint 3–10 不预建假字段或入口）；
- 财务备注。

### 6.5 页面动作

草稿页：

- “保存草稿”；
- “保存并提交财务确认”；
- “删除草稿”（仅无业务引用且有权限）；
- “取消”。

校验错误显示在字段下方，同时在页首列出可点击错误摘要。保存失败不得清空已填写内容或已成功上传附件。

## 7. 财务确认页

待财务确认列表显示草稿号、名称、实物分类、部门、责任人、购置日期、原值填写状态和提交时间。

详情采用左右布局：左侧是实物资料与照片，右侧是财务确认表单。

### 7.1 会计认定交互

必选项：

- “固定资产”；
- “受控非固定资产”。

无论选择哪一种会计认定，原值都始终显示并强制填写，允许输入 0，但不允许为空或为负数；期初累计折旧和减值允许明确输入 0，已确认的 0 不得保存为空值。

选择“固定资产”时显示并强制校验固定资产类别、入账/达到可使用状态日期和折旧配置。选择“受控非固定资产”时隐藏并清空尚未确认的固定资产类别和自动折旧配置，但不隐藏或清空原值；V1 的期初累计折旧和减值固定显示为只读 0，后端同样拒绝非 0 或空值，不生成折旧/减值记录。

原值达到或超过当前提示阈值且选择“受控非固定资产”时，显示黄色警告并要求填写“非固定资产认定说明”。低于阈值仍可选择固定资产，不显示阻断。

### 7.2 动作

- “保存财务资料”：保持待财务确认；
- “退回更正”：必须填写更正原因，状态回草稿；
- “确认并生成正式编号”：显示不可逆提示，确认后事务内生成正式编号和二维码 Token，进入待贴标；
- “返回列表”。

按钮文字不得使用“审批通过”“审批拒绝”。页面不得显示审批人、审批流程或审批意见配置。

确认弹窗明确显示：“正式编号生成后永久占用，不因后续更正、换码或处置而复用。”请求处理中禁用重复点击；成功页显示正式编号和“加入标签打印队列”。

## 9. 正式资产变动交互

### 9.1 调拨/责任人/位置变更

模态框固定显示变更前值，并要求：

- 目标部门；
- 新责任人；
- 新位置；
- 生效日期；
- 原因；
- 备注。

仅变化字段需要选择新值，但三项组合必须最终有效。部门经理若选择范围外目标，页面直接提示“无权调往该部门，请由设备部或财务执行”，后端同样拒绝。

新责任人的候选列表只返回当前公司满足 `employment_status='active' AND is_active=true` 的员工；`leaving`、`resigned` 和已停用员工不显示。即使通过旧页面、篡改请求或直接 API 提交上述人员，后端也必须拒绝领用、调拨和责任人变更，提示“离职处理中/已离职/已停用员工不能接收新资产”。

### 9.2 借出/归还

借出表单先选择“借用方类型”：

- 内部员工（`borrower_type=internal_employee`）：显示当前公司满足 `employment_status='active' AND is_active=true` 的员工选择器，提交结构化 `borrower_employee`，`borrower_name` 和 `borrower_organization` 为空；姓名和部门从员工主数据只读展示，服务端另存不可编辑 `borrower_name_snapshot`，不显示手填借用人/单位。`leaving`、`resigned` 和已停用员工不在候选中，后端对篡改请求同样拒绝。
- 外部借用方（`borrower_type=external`）：`borrower_employee` 必须为空，显示手填借用方姓名 `borrower_name`（必填）和单位 `borrower_organization`（可空）。

两类共同字段为借出日期、预计归还日、经办人、原因和备注。切换类型时必须清空另一类型字段，详情卡片明确显示“内部员工”或“外部借用方”，不得只显示无法追溯的姓名文本。

归还表单：实际归还日、接收人、接收部门、责任人、位置、归还后状态（默认借出前状态）和备注。若有权用户选择另一 `in_use/idle` 状态，后端必须在恢复借出前状态后同时生成明确的状态变动历史。借出卡片在详情页显示预计归还日和是否逾期。

### 9.3 闲置、启用、送修和维修完成

每个动作均显示当前状态、目标状态，要求生效日期和原因。送修填写送修说明；维修完成填写完成日期和结果。页面明确提示“V1 仅记录维修占用状态，不生成维修工单”。

所有资产操作对象数量固定为 1，动作表单不显示数量输入。

## 10. 编码规则页面

编码方案编辑器允许按顺序组合：

- 固定文本；
- 公司编码；
- 实物分类编码；
- 部门编码；
- 年；
- 年月；
- 完整日期；
- 顺序号；
- 自定义固定文本。

V1.1 页面、导入模板和 API 枚举均不得提供 `custom_field` 片段。读取到历史或异常配置中的 `custom_field` 时，页面只读显示“V1.1 未启用此取值器”，并禁止将该方案启用或用于正式发号。

页面提供实时预览和“生成 10 个示例”。预览和示例必须标记“仅预览，不占正式序号”，不得写入正式计数器或编号登记。

已发放过正式编号的方案版本只读。修改时按钮为“复制为新版本”，要求设置生效时间；生效冲突时阻止保存并指出冲突方案。

## 11. 标签打印与贴标

### 11.1 打印队列

标签打印页默认筛选 `ready_to_print`，也可查看 `printed` 和 `attached`。列表显示当前二维码缩略图、编号、名称、部门、责任人、位置、标签状态和最近打印时间。二维码缩略图只对有标签操作权限的用户输出，并通过禁止缓存的受保护响应提供。

用户勾选资产后点击“生成 A4 预览”。后端在同一事务固定本次标签快照，记录打印批次、操作人和时间，把批次、明细及当前二维码状态置为 `printed`，随后直接打开 A4 预览；不再显示独立的“确认已完成打印”。每张标签默认显示：

- 公司简称；
- 资产名称；
- 正式编号；
- 部门；
- 二维码。

用户可以在本批次统一勾选责任人、位置、型号三个可选显示项。A4 预览必须保持二维码可扫描；按 100% 实际尺寸打印时二维码正方形边长不得小于 20 mm，并显示“请使用实际大小/100%，不要适合页面缩放”的打印提示。

浏览器无法可靠判断纸张是否真正输出，因此页面不要求用户返回后重复确认。打印失败时直接重新打印并新增一条打印批次记录；二维码保持 `printed`，不会因此自动变为已贴标。

贴标前重打使用当前 Token，并新增打印批次。

资产详情在当前二维码旁提供“查看二维码”和“打印二维码”。查看入口打开受保护的可放大原图；打印入口为当前资产直接建立单项 A4 打印批次并打开预览。二维码已记录为 `printed` 时按钮显示“重新打印二维码”并明确沿用当前 Token；已 `attached` 时不允许普通重打，只提供换标。

### 11.2 扫码或 Web 确认贴标

打印批次页逐项提供“手机扫码确认贴标”和“Web 确认贴标”入口。资产详情与标签队列在二维码生成后显示当前二维码缩略图；仅当前二维码状态为 `printed` 时显示 Web 确认按钮。Web 确认只能逐项执行，不提供整批一键附着。

扫码页和 Web 确认页均显示当前二维码、编号、名称、封面图、部门、责任人、位置和标签状态，并要求：

1. 勾选“已将此标签贴在该实物上”；
2. 确认当前部门、责任人和位置；
3. 对首次启用资产选择“在用”或“闲置”；
4. 点击“确认已贴标”。

只有当前 active 二维码身份、标签状态 `printed`、资料完整且用户有权限时按钮可用。两种方式调用同一幂等 Service，并记录确认方式。成功后标签状态变为 `attached`，首次启用资产离开 `pending_label`。

### 11.3 换标

已贴标资产详情的“换标”要求选择原因（损坏、遗失、无法扫描、信息重打、其他）并填写说明。确认后立即吊销旧 Token，生成新 Token，标签状态变为 `ready_to_print`；资产业务状态不改变。

旧标签扫码页只显示“此标签已失效，请联系资产管理员”，不得显示资产资料。新标签重新经过打印，并通过扫码或 Web 逐项确认。已为 `attached` 的资产不得绕过换标流程直接普通重印。

## 12. 手机扫码资产页

未登录时先跳转登录，登录后回到原扫码地址。有效且有权的二维码首屏显示：

- 封面照片；
- 名称、编号；
- 资产状态、标签状态；
- 实物分类；
- 部门、责任人、位置；
- 最近盘点；
- 最近保养（如适用）。

按权限和上下文显示“查看详情”“盘点”“完成保养”“确认贴标”。财务字段仅对 `finance`、`management` 显示。

错误状态分别显示：标签已失效、二维码无效、无权查看、资产已归档。无权查看时不得回显资产名称或编号。

Edge Android 从系统扫码入口打开局域网页面、或微信等受控应用内浏览器打开 Web 贴标页时，可能在可见 URL 正确的情况下提交 `Origin: null`，并携带应用壳自身的 HTTPS Referer；部分浏览器还会删除非标准隐藏字段。扫码和单资产 Web 贴标确认页须支持受限兼容，但不得关闭全局 CSRF：只有对应精确端点、请求 Host 精确属于 `QR_BASE_URL` 或无通配符的 `CSRF_TRUSTED_ORIGINS`、登录会话、CSRF Cookie 和有效表单 Token 全部匹配时才继续。服务器生成且绑定当前会话与精确 POST 路径的短时签名桥接令牌若存在必须有效；扫码确认缺桥时仅允许扫描 URL Token 与隐藏表单 Token 恒定时间一致。成功审计须区分“Edge 扫码兼容确认”和“Web 不透明来源兼容确认”；其他端点、篡改桥接令牌或缺少任一核心条件仍返回 403。

## 13. Excel 导入

页面固定四步：

1. 下载标准模板/上传文件；
2. 字段解析与校验；
3. 预览；
4. 确认创建草稿。

模板每一行代表一件资产，数量列固定填 1。任何空值、文本或非 1 数量均形成行级错误，不自动拆成多条记录。

错误表包含行号、字段、原值、原因；提供“仅下载错误行”。存在错误时不得只导入正确行，用户须修正后重新上传，避免误以为整批已完成。

确认页明确提示：“本次只创建草稿，不生成正式编号或二维码。”成功后显示创建数，并跳转导入批次草稿列表。

## 14. 折旧页面

### 14.1 折旧方案试算

确认折旧前显示：

- 原值、残值、可折旧金额；
- 方法、使用年限、起算规则和起止日期；
- 期初累计折旧、期初净值；
- 完整逐期计划表；
- 舍入及最后一期尾差说明。

按钮：“返回修改”“保存试算”“确认折旧方案”。理论试算使用醒目的“理论试算，不影响账面”标识。

### 14.2 月度折旧

页面按期间显示批次状态、资产数、计划金额、调整金额、确认金额和差异。流程为“生成试算 → 查看明细与错误 → 财务确认批次”。确认后按钮变为“查看”“冲销”，不允许编辑原分录。

工作量法在试算前提供当期工作量录入页，并校验单位和累计工作量。具体公式和示例以 `docs/08-Depreciation-Calculation-Spec.md` 为准。

## 15. 盘点管理

### 15.1 创建任务

字段：任务名称、类型、范围、计划开始/结束、执行人、备注。

类型：部门盘点、财务全盘、专项盘点。范围：全公司、部门、实物分类、位置、勾选资产；可选范围按角色限制。

保存草稿后显示“预计应盘 N 项”及快照预览。点击“发布并生成快照”弹出提示：“发布后应盘快照不随调拨变化。”确认后进入进行中。

### 15.2 手机扫码

任务页固定显示：应盘、已盘、异常、未盘四个数字和进度条。扫描后显示快照值与现场录入值；位置、责任人、状态逐维比较，后端按结果显示：

- 正常；
- 位置异常；
- 责任人异常；
- 状态异常；
- 多项异常（上述两项或三项同时不一致，逐维展示）；
- 其他异常。

三维异常由现场值与快照自动派生，用户不能只选一个来覆盖其他差异；“其他异常”必须填写说明。支持上传差异照片。重复扫描显示历史，用户必须确认哪一条为有效结果。

扫描系统内但不在快照的资产时，显示“非本任务资产”，只允许返回任务，不计入已盘。发现无二维码/系统无记录实物时点击“登记盘盈”，填写临时名称、实物分类建议、发现位置、发现人、说明，并至少上传一张照片；不得先建立虚假资产。

### 15.3 差异工作台

进入差异处理后分为：未盘、位置异常、责任人异常、状态异常、其他异常、盘盈。

每项显示快照、现场结果、扫描人、时间、照片及处理状态。处理按钮固定为：

- “执行主档变动”；
- “确认主档无误”；
- “确认盘亏/转处置”；
- “其他处理结论”。

“执行主档变动”调用正式调拨/状态动作并回写关联记录；不得直接把扫描值覆盖主档。盘盈页仅 `finance` 显示“转资产草稿”，并保留盘盈来源。

未盘行对 finance、equipment 和范围内 department_manager 显示“受控补盘”。点击后必须重新扫描当前 QR、填写补盘原因并提交；任务保持差异处理中，不重新开放普通扫码。补盘结果正常时以该 supplemental Scan 为证据，异常时转入对应差异并仍需处理结论。普通执行人/Assignee 不显示此按钮。

页头持续显示未形成结论数。该数不为 0 时“关闭任务”禁用并说明剩余项目。有该任务类型关闭权限的角色在已发布任务上可见“取消任务”，必须填写原因；财务全盘仅 finance，专项为 finance/equipment，部门任务为 finance/equipment/范围内 department_manager。普通执行人即使被指派也不显示取消入口。

关闭后快照和原结论只读；同样具备原任务关闭权限的角色可从具体结论打开“新增更正”，填写更正原因并创建指向原结论的新记录，任务保持 closed 且不重开扫码。其他角色只看到更正历史。

## 16. 保养管理

### 16.1 保养计划

字段：资产、计划名称、周期数值、周期单位、责任人、首次到期日、上次完成日、下次到期日、标准内容、提前提醒天数、状态。

周期单位下拉框仅有日、周、月、年，不显示运行小时。计划状态操作为启用、暂停、终止；修改周期页面提示“仅影响未来到期日，不改写历史”。

### 16.2 待保养与完成

待保养分为“即将到期”和“已逾期”，显示剩余/逾期天数、资产、计划、责任人和到期日。手机完成页字段：

- 计划日期、实际完成日期；
- 完成人；
- 实际内容；
- 结果：正常/发现问题；
- 问题说明；
- 照片/附件；
- 备注。

选择“发现问题”后问题说明必填，V1 不显示未定义的严重级别字段。点击“确认完成”后记录只读并更新下次到期日。只有 equipment 看见“作废记录”，填写原因后原记录/附件保留；作废后的“重新完成”入口只对当前仍满足该计划完成权限的计划责任人或矩阵允许的范围角色显示，并重新鉴权。V1 不另建隐含的保养指派表。

### 16.3 问题跟进

问题跟进列表显示资产、保养记录、问题说明、发现人、发现日期、状态和跟进附件；发现人/日期只读取源 MaintenanceRecord 的完成人/实际完成日。设备角色填写处理说明后关闭，系统保存关闭时间；部门经理只能关闭授权范围内项目。跟进证据挂问题记录而不是资产根对象。源完成记录已作废时显示“来源保养记录已作废”，保留问题/附件历史但不允许继续关闭。页面提示该功能仅记录跟进，不是维修工单。

## 17. 离职资产清退

### 17.1 清退列表

显示员工、部门、发起时间、资产总数、已处理、未处理、状态。未处理数使用红色徽标。

HR 把人员设为“离职处理中”后系统自动创建清退单，快照该员工发起时当前负责的非终态资产和以 `borrower_employee` 关联的未归还内部借用资产；若已有未完成清退单则打开原单，不重复创建。状态切换成功后，所有新领用、转交、调拨和内部借用页面立即从候选列表移除该员工，后端也必须阻断旧页面或直接 API 请求。

### 17.2 清退详情

每项资产显示编号、名称、状态、部门、责任人、位置和处理状态，动作固定为：

- 归还；
- 转交；
- 处置。

HR 只看到状态和证据，不显示代为完成按钮。归还和转交打开正式资产变动表单；处置跳转处置流程并在返回时显示“处置中/已完成”。终态处置项标记“最后责任字段仅供历史显示”。“刷新/重新核对”只对 HR 显示；动态刷新只补入关联生效时间不晚于清退发起时间、但发起后才被发现或因既有关联资产状态变化而变为应清退的项目。此类项目显示“后补发现”，并展示原关联生效时间、发现时间和补入原因。页面不得提供“清退期间新增/转入”入口，也不得用动态补入绕过离职员工禁止接收新资产的规则。

页头“完成清退”仅对 HR 显示，未处理数大于 0 时禁用并列出阻断资产。首次清退未处理数为 0 后，完成弹窗强制填写实际离职日期，显示入职日和当前上海业务日边界；成功后写 `termination_date` 并把员工改为“已离职”，不使用服务器默认日期。

completed 单只读，不显示“重新打开”。若后续发现遗漏，HR 从原单点击“建立补充清退”，填写原因后新建指向原单的清退；员工保持已离职和原离职日期。已有 open/blocked 补充单时直接打开该单，其他角色无此入口。补充单完成页不再要求或改写离职日期。

## 18. 报废、出售与其他处置

### 18.1 发起页

显示资产当前非财务摘要及发起前状态。字段：

- 处置类型：报废/出售/其他处置；
- 申请日期、拟处置日期 `planned_disposal_date`；
- 原因、说明；
- 经办人、接收方/去向。

发起页不显示或提交实际完成日期 `actual_disposal_date`。拟处置日期只用于计划和提醒，旁边固定提示“不会据此锁定财务快照或完成处置”。借出资产显示阻断提示并提供“先办理归还”链接。确认发起后资产进入处置处理中。

### 18.2 财务核对区

有完成权限的 `equipment` 或 `finance` 先填写“实际完成日期” `actual_disposal_date`；按类型分别显示为“报废日期”“出售日期”或“实际处置日期”。该日期不得早于申请日期、不得晚于当前上海业务日，且在财务锁定前可以更正。

仅 `finance` 显示金额：截至实际完成日期的原值、累计折旧、减值、净值和处置收入。数值来自权威财务记录；除处置收入及财务备注外不提供手工覆盖。实际完成日期为空时，“锁定财务快照”禁用，拟处置日期不得替代实际完成日期参与计算。

点击“锁定财务快照”后显示锁定人、锁定时间和本次采用的实际完成日期，该日期及快照金额转为只读。非财务角色只看到绿色“财务已核对”或红色“财务未核对”。锁定后发现日期错误时，页面只提供“取消本次处置并重新发起”，要求原因并保留原记录，不提供直接改日期入口。

### 18.3 完成与取消

完成表单按类型要求：

- 报废：复用已锁定的实际完成日期并显示为报废日期，填写原因、经办人、至少一张报废现场照片；
- 出售：复用已锁定的实际完成日期并显示为出售日期，填写接收方、处置收入、至少一份出售证据；
- 其他处置：复用已锁定的实际完成日期并显示为实际处置日期，填写原因、接收方/去向、至少一份处置证据。

实际完成日期为空或财务未核对时“完成处置”禁用。成功后以实际完成日期作为终态生效日和折旧截止口径，进入相应终态并显示永久财务快照；拟处置日期仍作为计划字段单独显示。

未完成前显示“取消处置”，原因必填。终态不显示编辑或删除，只对 `finance` 显示“处置冲销”；冲销页列出将恢复的状态、阻断条件，并要求输入原因后二次确认。

## 19. 报表与 T+ 对账导出

报表中心固定提供资产总账、固定资产、折旧、部门、人员、设备、模具工具、盘点、保养和处置报表。筛选条件、页面合计和导出合计必须一致。

“T+ 对账导出”仅 `finance` 可见。页面的期间选择、校验、导出批次、文件结构、口径说明和差异处理严格实现 `docs/11-Tplus-Reconciliation-Export.md`，不得用普通固定资产导出按钮代替。

每次导出结果页显示文件名、期间、口径版本、导出人、导出时间、资产数、金额合计和下载按钮；历史导出只读保留。V1.1 页面不得出现“同步 T+”“推送 T+”或“自动记账”。

## 20. 操作日志

Sprint 11 交付只读操作日志页。筛选项为时间范围、操作者、动作、对象类型、对象 ID 和 correlation ID；默认最近 7 天，结果分页显示时间、操作者、动作、对象、脱敏后的变更前后摘要和关联 ID，不提供编辑、删除或普通导出。

system_admin 查看公司全域；finance 只看本人及财务对象白名单；hr 只看人员/清退对象及本人 HR 动作；其他角色即使直接访问 URL 也拒绝。前后摘要继续执行字段级脱敏，不显示 Token、Secret、Cookie、文件内容或无权 A1 信息。页面不得允许通过手填 object_type 绕过服务端白名单。

## 21. 附件交互

附件区按业务对象和类型分组，显示文件名、类型、大小、上传人、上传时间、有效/作废状态和备注。

- 上传前选择附件类型；财务附件类型只对有权限用户提供。
- 支持拖放和手机拍照；上传成功后才允许提交相关业务动作。
- 已进入正式流程的文件只有“查看/下载/作废”，不显示删除；作废必须填写原因。
- 作废附件仍在“显示作废文件”筛选中可见，默认折叠。
- 无权附件不显示文件名、类型或数量。
- 盘盈、盘点扫描、保养、清退、处置页面均在本业务页面上传附件，不要求先存在正式资产。

## 22. 用户权限页面

`system_admin` 可在用户列表创建普通应用用户。创建时填写用户名、显示名称、可选联系方式、
新用户密码、固定角色、原因和当前操作人密码；不得提供 staff、superuser 或自定义权限开关。
若选择 `department_manager`，创建表单必须同时要求一个启用部门范围，并在同一事务内完成
用户、范围、角色和审计写入。

`system_admin` 在用户详情中配置一个或多个角色；选择 `department_manager` 时必须选择授权部门，并明确“包含下级部门”开关，默认开启。

页面以只读摘要展示该用户最终权限：角色、数据范围、财务字段可见性、可执行关键动作。授予或移除 `finance`、`system_admin` 时要求二次确认并填写原因。

页面不得提供自定义角色或逐按钮自由授权；V1.1 权限以 `docs/07-Permissions-and-Workflows.md` 固定矩阵为准。

## 23. 状态、错误与安全确认

### 23.1 状态样式

- 草稿/待确认/待贴标：蓝或黄；
- 在用：绿；
- 闲置/借出/维修中：灰或橙；
- 处置处理中：橙红；
- 已报废/已出售/已其他处置/已归档：深灰。

颜色之外必须同时显示中文文字，不能仅靠颜色表达。

### 23.2 错误信息

错误必须说明对象、字段、原因和下一步，例如：“资产 A-001 尚未锁定处置财务快照，不能完成处置；请联系财务核对。”禁止只显示“操作失败”。

并发冲突显示记录已被谁/何时更新（有权限时）并要求刷新，不静默覆盖。正式编号并发失败必须完整回滚，不在页面猜测下一个编号。

### 23.3 二次确认

以下动作必须显示影响摘要并二次确认：财务正式化、折旧批次确认/冲销、换标、盘点发布/关闭、清退完成、处置完成/冲销、归档、权限变更、备份恢复。

## 24. 响应式与可用性

- 手机端触控按钮最小高度 44 px；扫码主操作固定在拇指可达区域。
- 盘点、贴标和保养完成页在弱网络下不得因重复点击生成重复业务记录；提交按钮在请求期间禁用，服务端使用幂等保护。
- PC 表格支持横向滚动、固定表头、分页和筛选条件回显。
- 所有表单支持键盘操作；输入框有可见标签；图片有替代文本；状态不只依赖颜色。
- 403 页面不显示对象敏感信息，并提供返回有权页面入口。

## 25. UI 验收

UI 验收必须逐角色验证桌面端和手机端，覆盖：

- 实物分类与会计认定在不同区域，不能相互自动决定；
- 数量恒为 1，导入及所有动作无部分数量入口；
- 财务确认页面不出现审批引擎概念；
- 正式编号生成、受保护的 Web 二维码缩略图、A4 打印、扫码或 Web 逐项贴标、换标及失效 Token；
- 资产完整状态动作；
- 盘点快照、异常、盘盈和关闭阻断；
- 保养提醒、完成、作废和问题跟进；
- 离职未清阻断；
- 三类处置、财务快照和冲销；
- 首页“报废”卡片及全部指标口径；
- 不同角色的数据范围、财务字段、附件和导出隔离；
- T+ 对账专用导出；
- 正式资产无删除按钮。

详细 UAT 步骤和证据以 `docs/12-UAT-Acceptance.md` 为准。
