# 验证与交付指南

更新：2026-09-09。按 [AGENTS.md](../AGENTS.md) 和本次改动选择验证，不要求所有任务套用整套 Sprint 门禁。原 140 行清单保存在 [历史原文](archive/Sprint-Definition-of-Done-Reference.md)。

## 按影响选择检查

| 改动 | 需要核对的结果 |
|---|---|
| 纯文档 | 当前事实、文档定位、路径与链接、重复和冲突；确认没有顺带修改源码和数据 |
| 页面和交互 | 相关操作成功与错误反馈、必要的角色拒绝和手机布局；已有后端限制仍能执行 |
| 业务逻辑 | 相关单元和服务测试、边界输入、失败回滚及幂等，按影响补回归 |
| 金额计算 | 明确业务口径与例子，用 Decimal 精确断言验证舍入、期间、尾差和历史影响 |
| 权限 | 允许与拒绝路径、跨公司/部门、敏感字段与附件；明确变化后的访问范围 |
| 数据库结构 | 跟踪迁移、空库与相关升级路径、历史记录保留，检查未生成的模型变化 |
| 锁和并发 | 在 PostgreSQL 验证关键竞态与事务完整性，SQLite 仅作为适用的快速检查 |
| 部署、备份、恢复 | 在目标或隔离环境验证版本、数据隔离、可恢复性、关键访问与实际操作权限 |

测试命令和环境准备集中在 [开发指南](Development-Guide.md)。相关检查通过后，按影响和可行性决定是否需要全量回归；存在未解决失败时说明影响，不能隐去失败或沿用旧报告的通过数字。

## 需求与已有行为冲突

- 普通界面或内部实现可根据用户目标优化，不因 AI 参考稿不同就机械停止。
- 金额结果、状态含义、访问权限或历史数据的变化需要说明影响；现有授权不足且确实缺少决定时，只暂停依赖该决定的部分。
- 测试可能记录旧行为。需求变化时说明为什么调整断言，保留仍然有效的正确性、权限和数据保护检查。

## 完成时说明什么

简述完成内容、修改文件、实际运行的验证及剩余问题；涉及数据库迁移、业务口径或部署时补充相应结果和限制。文档任务不必使用七段 Sprint 报告，也不要求为了合格而运行无关业务测试。

## 区分证据性质

- 自动测试通过：只说明该代码、环境和用例的结果。
- 人工使用验收：说明实际岗位和终端完成了哪些操作。
- 生产环境验证：说明目标环境、备份恢复及发布是否实际验证。
- 历史 UAT：保留原始结果，用于参考；不能自动证明今天的代码或环境通过。
