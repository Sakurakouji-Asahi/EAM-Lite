# Definition of Done V1.1

本文件适用于 Sprint 0–12。当前 Sprint 只有在以下所有适用条件满足并提供证据后，才可标记为完成。

## 1. 范围与需求

- 只实现当前任务文件列出的范围。
- 当前任务列出的排除项未被提前实现。
- 已阅读 `AGENTS.md`、当前任务和任务列出的相关文档。
- 实现可追溯到明确的业务规则、验收条件或技术约束。
- 文档与现有实现存在冲突时，已在编码前报告并获得明确口径；不得把未确认假设作为完成项。
- 未删除、覆盖或重置用户已有的无关改动和数据。

## 2. 代码与依赖

- 代码位于仓库约定结构中，没有创建第二层仓库或无必要的嵌套项目根目录。
- 新增或升级依赖具有明确用途，采用项目已选定的兼容版本策略，并在依赖/锁定文件中记录精确解析版本。
- 在干净环境中可按 README 重复安装依赖。
- 未提交 Secret、密码、Token、私钥、真实数据库凭据或真实 `.env`。
- 没有为了通过测试而删除、跳过或放宽既有有效测试。
- 没有遗留会影响当前验收的占位实现、静默失败或未说明 TODO。

## 3. 数据库与迁移

- 所有 schema 变化均由已跟踪迁移完成。
- 从空 PostgreSQL 数据库执行全部迁移成功。
- 从上一 Sprint 的数据库状态升级到当前迁移成功，并保留已有数据。
- 迁移检查确认没有未生成或未应用的模型变化。
- 唯一约束、检查约束、索引、空值规则和删除策略与业务规则一致。
- 关键跨表约束若无法用数据库约束表达，必须由唯一业务 Service 在原子事务中执行，并有绕过/失败测试。
- 正式历史数据没有通过迁移被重写、复用或物理删除。

## 4. 事务、并发与幂等

- 多表业务操作使用清晰的事务边界；任一步失败时不得留下半完成状态。
- 修改当前资产状态的流程先锁定或以等效方式保护目标记录，并重新验证前置状态。
- 编码、月度计提、盘点扫描、保养完成、离职清退等可能重试的操作定义幂等或重复提交行为。
- 依赖 PostgreSQL 锁、约束或隔离级别的能力必须在 PostgreSQL 上测试；SQLite 测试不能替代。
- 并发测试需证明无重复、无丢失更新，失败事务不会留下孤立业务记录。

## 5. 权限、安全与审计

- 页面按钮、View、Service、导入导出和直接构造请求均实施后端权限校验。
- 按 `docs/07-Permissions-and-Workflows.md` 验证允许角色、拒绝角色、部门数据范围和财务字段隔离。
- 至少包含一个获准访问测试和一个越权拒绝测试；涉及对象范围时还需跨部门拒绝测试。
- 关键新增、修改、确认、冲销、状态变化、导入、导出及敏感下载按规则写入 AuditLog。
- 审计日志包含操作人、时间、对象、动作及必要的修改前后值，且不包含密码、Secret 或 Token 原文。
- 上传文件验证扩展名、实际类型和大小；业务附件不通过不受控公开 URL 暴露。
- CSRF、会话、登录跳转和停用用户访问行为符合 Django 安全默认及项目配置。

## 6. 自动测试

- 当前 Sprint 任务列出的单元、Service、权限、事务、导入导出和回归测试全部通过。
- 现有完整测试套件通过。
- 测试框架固定为 pytest + pytest-django，准确命令在 README 中固定；Completion Report 中记录命令、退出状态和测试数量。
- 金额测试使用 Decimal 精确断言，覆盖舍入、残值底线和最后一期修正等适用边界。
- 日期测试覆盖月末、年末、闰年和上海时区等适用边界。
- 测试不依赖执行顺序、真实生产数据或外部公共互联网。
- 若必需的 PostgreSQL、浏览器、打印或恢复环境不可用，必须标记为阻塞/未完成，不得用“待后续验证”关闭 Sprint。

## 7. UI 与可用性

- 用户可见页面使用中文标签和可理解的错误信息。
- 表单错误定位到具体字段；批量操作错误定位到具体行、字段、值和原因。
- 相关 PC 页面在 Chrome、Edge 的项目支持版本中完成冒烟验证。
- 相关扫码、盘点和保养页面在手机宽度下无横向溢出，主要操作可完成。
- Bootstrap、HTMX 等运行时前端资源保存在本地静态目录，不依赖公共 CDN。
- 财务字段、按钮和导出入口不会仅靠前端隐藏来控制权限。
- 破坏性或不可逆操作提供清晰确认、原因输入及结果反馈。

## 8. 文档与运维

- README 已同步环境要求、安装、配置、迁移、管理员创建、启动和测试命令。
- `.env.example` 包含新增配置项但不含真实值。
- 新增定时命令、导入模板、导出格式、备份/恢复或部署步骤均有使用说明。
- 依赖操作系统或计划任务的功能提供可人工复现的管理命令，不把关键逻辑只藏在 Web 请求或服务器配置中。
- 已记录本 Sprint 的数据迁移、兼容性影响和明确限制。

## 9. Sprint 验收证据

Completion Report 至少包含：

### Completed

- 对照当前 Sprint 验收条件逐项说明结果。

### Files Changed

- 列出新增、修改和删除的文件。

### Database Migrations

- 列出迁移名称、空库迁移结果和升级迁移结果。

### Tests

- 列出执行命令、数据库类型、测试数量和结果。
- 对 PostgreSQL 并发、浏览器、Excel、备份恢复等专项验证单独列证据。

### Business Rules Verified

- 列出实际验证的 BR 编号或对应需求。

### Not Implemented

- 只列当前 Sprint 明确排除或后续 Sprint 内容，不得隐藏未完成验收项。

### Risks / Follow-up

- 列出仍存在但不阻止当前验收的真实限制；说明为什么不影响当前 Sprint。

## 10. 停止条件

出现以下任一情况，当前 Sprint 不得声明完成：

- 任一必需测试失败、被无依据跳过或只在 SQLite 上验证了 PostgreSQL 专属行为。
- 存在未应用迁移、不可重复安装、缺失环境变量说明或未锁定依赖。
- 已知越权路径、敏感字段泄露、公开附件、明文秘密或关键流程缺少审计。
- 发生文档冲突、关键业务口径缺失或需要扩大当前 Sprint 范围才能继续。
- 事务失败会留下半成品、正式编号可能重复/复用、确认历史可能被覆盖。
- 当前 Sprint 的用户验收路径不能从界面或有文档的管理命令完成。

满足全部 DoD 后，Codex仍必须停止并等待人工验收；不得自动进入下一 Sprint。

## 11. V1.2 低值物品补充门禁

每个低值物品 Sprint 仍只验收当次授权范围。Sprint 13 必须额外证明：

- `Asset.quantity=1` 与现有资产、财务、盘点、清退功能未被修改或破坏；
- supplies 三类基础档案的公司边界、规范化唯一约束、树循环、员工状态、
  管理模式和非负最低库存同时受 Service/模型及可表达的数据库约束保护；
- 分类、仓库、物品新增/修改/停用及物品导入确认写入现有 AuditLog；
- 物品 `.xlsx` 上传、校验、预览、整批确认、回滚和重复确认幂等可执行；
- 页面和直接 POST 使用相同后端权限，列表分页；
- 没有库存余额、库存流水、过账、领退调拨、保管、盘点、清退或报表代码
  被提前作为 Sprint 13 交付。

库存余额可由流水重建、无负库存、过账幂等、保管清退和完整 `docs/16`
UAT 是后续 Sprint 14–18 的累积门禁，不能用 Sprint 13 的基础档案完成来
宣称整个低值物品模块已完成。
