# 操作日志撤销

在“基础资料与设置 → 操作日志”中，找到“建立实物资产”或“确认资产初始化导入”记录，点击“撤销”，核对影响范围、填写原因后确认。

- 撤销建档：退回原资产草稿，保留填写的实物和财务草稿资料。
- 撤销资产初始化导入：整体移除该批资产和财务草稿，包括符合条件的建档；批次变为“已撤销”。源文件、导入明细、原操作日志和撤销记录保留，同一文件可重新上传。
- 编号释放：撤销未投入使用的建档时，删除对应发号登记、编码身份、二维码和发号历史，回退相应末尾流水。重新建档可再次取得这些编号。原二维码失效；新的二维码使用新的随机标识。

只允许撤销未打印标签、未确认财务、没有借用、盘点、保养、处置、对外引用等后续业务的记录。编号必须位于对应范围末尾；已有后续编号时，需先撤销后建档记录。其他日志目前只供查询，不提供自动撤销。

办理人须有操作日志查看权限，并具有财务、设备或仓储的资产业务办理权限；含财务草稿的导入还要求财务权限。仅有系统管理员或人事权限不获得资产业务撤销权。确认时重新校验当前资料、下游引用和编号，任何一项失败均整批回滚；重复提交只返回原撤销结果。

## 部署

运行数据库迁移，并由迁移身份运行 `grant_runtime_database_privileges` 刷新 runtime 权限。发号相关四张表的 DELETE 仅在数据库触发器认可本次事务撤销计划时允许；TRUNCATE 不开放，操作日志和撤销记录仍只允许追加。重启应用后生效。

上线前备份数据库与附件。迁移本身可回退；已执行撤销后，恢复业务数据应使用备份或重新导入，不能通过回退代码恢复资产。

## 业务决定

2026-09-24，用户要求撤销本批建档和导入，并明确要求编号可再次使用。本次例外仅适用于上述未投入使用、无后续引用的撤销流程；其他已使用编号继续保持原有历史保护。
