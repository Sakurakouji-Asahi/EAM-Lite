## 1. LV 实物列表仍依赖财务确认

新建入口已经为“逐件低值耐用品”设置首次属性 LV，但列表筛选仍强制要求已确认的财务认定为 `controlled_non_fixed`。这与“先建档，财务以后确认”的操作顺序衔接不完整。

隔离 PostgreSQL 中实际建立 `LV-02-2020-000001-00` 后，资产存在于总资产台账，逐件低值耐用品列表却没有它。财务随后确认非固定资产后，同一编号才进入该列表，未发生资产丢失。

建议按首次管理属性组织实物管理列表，单独提供财务认定和待确认状态筛选；保留旧记录兼容逻辑和既有财务报表含义。修复前可从总资产台账查到新建记录。

代码：[列表筛选](D:/资产管理/apps/assets/list_filters.py:108)，[LV 新建入口默认值](D:/资产管理/apps/assets/views.py:408)。复现证据：`var/project-review-20260912/lv-list-gap.json`。

## 2. 导入模板未衔接新编码字段

当前资产导入模板为 `asset-initialization-v2`，缺少首次管理属性、单独指定的编码年份及依据、组件归属等新字段。导入确认仍只创建实物草稿，其首次管理属性为空。

使用实际模板生成器、文件上传校验和确认服务完成一行导入后，直接办理建档返回：“请选择首次建档管理属性；该属性不代替财务认定。”确认建档页面仅有确认项，也不能在此补填该属性。返回草稿编辑可以补齐，但批量导入时会变成逐条操作。

建议扩展模板、行校验和保存映射，至少先补齐首次管理属性与年份依据，并在导入预览中提前指出缺失项。旧模板需有明确兼容处理，不能从财务认定自动猜测首次属性。

代码：[导入模板定义](D:/资产管理/apps/imports/services.py:143)，[行数据映射](D:/资产管理/apps/imports/services.py:2238)，[确认建档表单](D:/资产管理/apps/assets/forms.py:333)。复现证据：`var/project-review-20260912/import-standard-gap.json`。

## 3. 日期回显修正未覆盖全部模块

资产、财务和基础资料表单此前已修正日期格式，但资产盘点、保养、物品盘点仍能输出以下内容：

```html
<input type="date" value="2026/09/12">
```

日期控件要求 `2026-09-12`。现有写法会让浏览器无法正确显示初始化或编辑时传入的日期，用户需要重新填写；这不是数据库中的日期已丢失。

本轮在上述 3 个模块分别复现，另在当前开发环境只读生成的盘点和保养表单中确认同样输出。建议统一日期控件格式，并验证编辑回显与校验失败后的回显。

代码：[资产盘点日期](D:/资产管理/apps/inventory/forms.py:68)，[保养首次到期日](D:/资产管理/apps/maintenance/forms.py:46)，[物品盘点默认日期](D:/资产管理/apps/supplies/forms.py:826)。复现证据：`date-inventory.json`、`date-maintenance.json`、`date-supply_inventory.json`，均在本轮证据目录。

## 4. 减少单次页面里的重复角色查询

当前开发库尚无资产，使用当前 haoren 账号只读渲染页面，得到以下查询次数：

| 页面 | 数据库查询总数 | 查询用户角色的次数 |
|---|---:|---:|
| 首页 | 171 | 124 |
| 初始化 | 111 | 84 |
| 人员 | 94 | 78 |
| 位置 | 92 | 76 |
| 资产台账 | 106 | 82 |
| 新建资产 | 159 | 76 |

首页的 124 次角色查询文本完全相同。原因是权限辅助函数每次重新访问角色关系，页面导航和功能权限判断重复调用这些函数。

建议在单次请求内复用角色信息，并继续在后台执行操作权限校验。这些次数来自本轮后端渲染检查，不是浏览器加载时间，也不是并发容量测试。

代码：[角色读取](D:/资产管理/apps/masterdata/permissions.py:60)，[页面上下文与权限判断](D:/资产管理/apps/core/context_processors.py:377)。证据：`var/project-review-20260912/live-snapshot-detailed.json`。

## 5. 增加按楼栋、楼层查看资产

你现在有三号楼下的 3 个楼层、30 个具体位置。台账的位置选项仅列出实际被资产使用的末级房间，筛选也只匹配该房间 ID；即使指定上级楼层 ID，也不会包含其下房间的资产。

隔离验证确认：房间可选，父级楼层不可选，父级筛选不返回该房间的资产。建议提供“楼栋／楼层／房间”的逐级筛选，并把上级位置下所有已授权房间一起纳入；盘点模块已有查询后代位置的实现可参考。

代码：[台账位置选项](D:/资产管理/apps/assets/views.py:310)，[精确位置筛选](D:/资产管理/apps/assets/list_filters.py:102)，[盘点位置范围](D:/资产管理/apps/inventory/services.py:428)。证据：`var/project-review-20260912/location-filter-gap.json`。

## 6. 让人员资料更容易查找

人员页目前只支持编号、姓名、手机号搜索，以及启用和任职状态筛选。已有部门字段未提供筛选，原表的岗位和“上化氟／莹润／小时工”标记保存在备注中，列表不展示这些信息。

建议先增加部门筛选和岗位、来源标记的简洁展示；如果后续经常按这些信息查询，再将其整理为独立字段，并保留原始备注与导入来源。这是使用体验建议，现有 56 名人员没有缺失。

代码：[人员查询条件](D:/资产管理/apps/masterdata/views.py:443)，[人员列表](D:/资产管理/templates/masterdata/employee_list.html:8)。本轮确认现有数量仍为 7 个部门、56 名人员。
