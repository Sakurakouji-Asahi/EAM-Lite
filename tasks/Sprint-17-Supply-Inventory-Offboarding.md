# Codex Task — Sprint 17：低值物品盘点与离职清退

## 前置

- Sprint 16 已验收。
- 仓库库存、保管余额和逐件低值资产路径完整。

本 Sprint 实现数量库存盘点、耐用品保管盘点以及现有离职清退的加法集成。不要开始最终综合报表和 Dashboard。

## 目标

实现：

- 仓库库存盘点；
- 数量型耐用品保管盘点；
- 盘点差异闭环；
- 数量型耐用品纳入现有员工离职清退。

## 必须实现

### 1. 盘点模型

按技术设计实现：

- `SupplyCountTask`
- `SupplyCountLine`

盘点域：

- `warehouse_stock`
- `custody`

状态：

- draft
- in_progress
- reconciliation
- closed
- cancelled

模型状态和快照字段只能由 service 修改。

### 2. 仓库库存盘点

实现：

```python
create_supply_count_task(...)
publish_supply_count_task(...)
record_supply_count(...)
stop_supply_count_entry(...)
close_supply_count_task(...)
cancel_supply_count_task(...)
```

规则：

- 发布时保存该仓库当前余额快照；
- 实盘数量非负；
- 差异 = 实盘 - 快照应盘；
- 关闭时自动生成一张 `count_adjustment` 单；
- 盘盈/盘亏成本按需求规则；
- 零库存盘盈必须输入单位成本；
- 每个差异行原因必填；
- 任务关闭和调整单过账同事务；
- 重复关闭幂等。

若发布后仍允许日常业务，详情必须显示快照后变动并在关闭前二次确认；不要静默把快照后业务当作盘点差异。可采用项目批准的简单方案：任务进行中时阻止该仓库新的低值物品过账，直到停止录入或取消。Codex 必须选择一种明确、一致且有测试的方案，不得混用。

推荐首期方案：发布仓库盘点后，阻止该仓库所有新库存过账；停止录入进入差异处理后继续保持冻结；任务关闭/取消后解除。这样业务最清晰、实现风险最低。

### 3. 保管盘点

- 按部门，可选员工创建任务；
- 发布时快照开放保管记录；
- 录入实有数量；
- 有差异时必须通过真实归还、转交、报损、报废或受控更正解决；
- `SupplyCountLine` 保存解决动作引用；
- 所有差异解决后方可关闭；
- 不自动修改保管余额。

逐件低值资产不进入此盘点，继续使用现有资产盘点。

### 4. 离职清退模型

新增 `EmployeeSupplyClearanceItem`。

对现有 `EmployeeAssetClearance` 加法迁移：

```python
total_supply_custodies_snapshot = PositiveIntegerField(default=0)
unresolved_supply_custodies = PositiveIntegerField(default=0)
```

不要重命名或改变现有资产字段，不迁移历史含义。

### 5. 清退服务集成

修改现有清退发起、刷新、解决和完成服务：

- 发起时锁定员工和必要业务记录；
- 创建现有资产清退项；
- 创建该员工所有开放、数量大于 0 的耐用品保管清退项；
- 低值易耗品历史领用不进入清退；
- 完成条件为资产未解决数和耐用品未解决数均为 0；
- 归还、转交、报损、报废后用实际 `SupplyCustodyMovement` 解决清退项；
- 补充清退沿用现有机制；
- 无 supplies 数据时，现有清退行为不变。

避免循环导入，按技术设计使用字符串模型引用和服务内局部导入。

### 6. 页面

实现：

- 盘点任务列表；
- 创建、发布、录入、停止、差异处理、关闭、取消；
- 仓库盘点差异和调整单跳转；
- 保管盘点差异和保管动作跳转；
- 现有离职清退详情增加“数量型低值耐用品”区块；
- 分别显示资产和耐用品未解决数量。

### 7. 权限

- 仓库盘点：warehouse、finance、system_admin 创建/执行/关闭；management 只读。
- 保管盘点：equipment、finance、system_admin；department_manager 可管理本部门范围；employee 只能录入本人被分配或本人范围。
- 离职清退：沿用现有 hr、finance、equipment、department_manager 等权限，不为 supplies 绕过现有矩阵。

只测试本模块和被修改清退流程的必要权限，不做全项目安全复审。
