# Codex Task — Sprint 16：低值耐用品保管与逐件资产集成

## 前置

- Sprint 15 已验收。
- 数量型耐用品领用可以建立保管记录。
- 逐件资产现有生命周期保持正常。

本 Sprint 完成数量型耐用品保管动作，并把逐件低值耐用品明确接入现有 `Asset + controlled_non_fixed`。不要开始盘点、离职清退和综合报表。

## 目标

实现：

- 数量型耐用品归还仓库；
- 责任转交；
- 报损和报废；
- 期初保管导入；
- 逐件低值耐用品入口、筛选和防折旧规则。

## 必须实现

### 1. 保管归还

实现受控服务：

```python
return_custody_to_warehouse(...)
```

要求：

- 支持部分和全部归还；
- 锁定来源保管记录和目标仓库余额；
- 使用保管成本；
- 同一事务减少保管、增加库存；
- 同时写库存退回流水和保管归还流水；
- 全部归还时保管数量、金额清零并关闭；
- 并发归还不得超量。

归还可以复用 `return` 单据，但耐用品退回行必须关联 `source_custody` 和原领用行。

### 2. 责任转交

实现：

```python
transfer_custody(...)
```

要求：

- 支持部分和全部转交；
- 新责任部门必填，员工可为空；
- 员工若填写，必须属于目标部门且在职、启用；
- 不改变仓库库存；
- 成本沿用来源；
- 来源减少，目标新建保管记录；
- 创建不可变 `transfer` 保管流水；
- 保留 `parent_custody` 来源链；
- 全部转交时关闭来源记录。

不要为了合并显示而把不同来源和不同成本批次自动合并。

### 3. 报损和报废

实现：

```python
write_off_custody(..., action="loss" | "scrap")
```

规则：

- 数量大于 0 且不超过当前保管数量；
- 原因必填；
- 减少保管数量和金额；
- 不增加库存；
- 创建不可变保管流水；
- 全部处理后关闭保管；
- 不生成会计凭证。

### 4. 期初保管导入

启用 `opening_custody`：

- 模板下载；
- 物品必须为 `durable_quantity`；
- 部门、员工同公司；
- 员工可为空，但如填写必须同部门、在职；
- 数量 > 0，成本 >= 0；
- 确认后建立保管记录和 `opening` 保管流水；
- 不改变仓库库存；
- 批次全有或全无、确认幂等。

### 5. 保管页面

实现：

- 当前保管列表；
- 按物品、部门、员工、状态筛选；
- 详情和来源链；
- 归还、转交、报损、报废入口；
- 历史保管流水；
- 员工“我的耐用品”页面。

### 6. 逐件低值耐用品

不得新建逐件低值资产表，不得修改 `Asset.quantity=1`。

实现：

1. 低值物品导航中的“逐件低值耐用品”跳转现有资产创建/列表。
2. 资产列表增加会计认定筛选：固定资产、受控非固定资产、未确认。
3. 对 `controlled_non_fixed` 显示“逐件低值耐用品/受控非固定资产”说明。
4. 财务确认仍使用现有 `AssetFinance`，不新增重复原值字段。
5. 所有折旧配置创建、激活和计提入口统一拒绝 `controlled_non_fixed`。
6. 固定资产折旧行为不变。
7. 受控非固定资产继续使用二维码、资产盘点、调拨、处置和现有离职清退。

### 7. 成本合计口径

增加服务级查询：

- 数量型耐用品仓库库存金额；
- 数量型耐用品开放保管金额；
- 二者合计；
- 逐件受控非固定资产原值单独查询。

不得把逐件资产原值重复并入数量库存金额。

### 8. 权限

- `warehouse`、`finance`、`equipment`、`system_admin` 可执行保管动作。
- `department_manager` 可在本部门范围发起/协助转交和归还，但最终过账权限按批准矩阵实现；至少不能跨范围操作。
- `employee` 只读本人保管；如提供“发起归还”仅生成请求草稿，不得直接改库存。本期默认不实现请求流，保持只读。
- `management` 只读。
