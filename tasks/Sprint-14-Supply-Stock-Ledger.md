# Codex Task — Sprint 14：库存单据、不可变流水与入库过账

## 前置

- Sprint 13 已验收。
- 基础档案和物品档案导入可用。
- 当前分支工作树干净。

开始前阅读低值物品需求、技术设计、数据字典和 Sprint 13 实际实现。

本 Sprint 只实现库存基础引擎、期初入库和日常入库。不要开始领用、退回、调拨、保管、盘点或清退。

## 目标

建立可核对、可并发、可回滚的库存权威流水和余额缓存，完成期初和日常入库闭环。

## 必须实现

### 1. 模型

按技术设计实现：

- `SupplyDocumentSequence`
- `SupplyDocument`
- `SupplyDocumentLine`
- `SupplyStockBalance`
- `SupplyStockLedger`

本 Sprint 启用单据类型：

- `opening`
- `receipt`

其他枚举可先定义，但页面和 service 不得提前开放。

### 2. 单据编号

- 使用 `transaction.atomic()` + `select_for_update()` 的序列表。
- 格式：`QC-YYYY-000001`、`RK-YYYY-000001`。
- 禁止 `MAX()+1`。
- 并发创建不得重复。

### 3. 草稿单据

实现：

```python
create_supply_document(...)
update_draft_document(...)
cancel_supply_document(...)
```

规则：

- 草稿不影响库存。
- 草稿可以修改明细。
- 草稿取消后不可恢复。
- 不提供已过账编辑。
- 单据头、行、物品和仓库必须同公司。

### 4. 过账

实现 `post_supply_document()`，仅支持期初和入库：

- 锁定单据；
- 校验状态和幂等；
- 按固定顺序锁定/创建余额行；
- 按 Decimal 规则计算金额和移动平均；
- 更新余额；
- 创建不可变流水；
- 保存行过账单价和金额；
- 更新单据状态；
- 写业务审计；
- 任一步失败整体回滚。

### 5. 不可变历史

- `SupplyStockLedger` 不允许 update/delete。
- 已过账 `SupplyDocument` 和 `SupplyDocumentLine` 不允许普通修改或删除。
- 操作人被删除时允许 FK `SET_NULL`，不得改变业务值。

### 6. 成本纯函数

在 `domain.py` 实现并测试：

- 数量、单价、金额量化；
- 入库金额；
- 新移动平均；
- 数量为 0 时金额和平均成本为 0；
- 0 成本入库原因校验。

不得使用 float。

### 7. 页面

实现：

- 单据列表；
- 新增期初单；
- 新增入库单；
- 草稿编辑/取消；
- 过账确认；
- 单据详情；
- 当前库存余额列表；
- 库存流水列表。

筛选：日期、单据号、类型、状态、仓库、物品。

### 8. 期初库存 Excel 导入

启用 `opening_stock` 导入类型：

- 下载模板；
- 行级校验；
- 确认后按仓库生成期初单草稿；
- 不自动过账；
- 确认幂等；
- 错误全回滚。

### 9. 权限

- `system_admin`、`finance`、`warehouse`：创建、编辑草稿、取消和过账。
- `equipment`、`management`：按需求只读。
- 其他角色仅在批准范围查看或无入口。
- 成本字段按需求矩阵控制。

只验证本模块必要权限和公司边界。

### 10. 核对命令

实现只读命令：

```text
python manage.py reconcile_supply_balances --company <code>
```

输出每个不一致的仓库、物品、流水汇总和余额缓存；无差异时退出码 0，有差异时非 0。此 Sprint 不实现自动修复。

## 关键约束

- 余额唯一：公司 + 仓库 + 物品。
- 数量/金额非负。
- 数量为 0 时金额和平均成本为 0。
- 单据和幂等键公司内唯一。
- 单据行号单据内唯一。
- 每条过账行只能产生一条对应入库流水。

## 自动测试

至少覆盖：

1. 单据号并发唯一。
2. 草稿不影响库存。
3. 期初过账。
4. 多次入库移动平均。
5. 0 成本入库必须有原因。
6. 重复过账幂等。
7. 中途异常整体回滚。
8. 流水不可修改/删除。
9. 已过账单据不可编辑。
10. 余额与流水核对命令。
11. 期初导入生成草稿及重复确认。
12. PostgreSQL 并发过账同一余额。
13. 公司和角色权限。
14. 现有完整回归测试。
