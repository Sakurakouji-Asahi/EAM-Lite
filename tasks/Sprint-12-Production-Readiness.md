## 生产部署

按 `docs/09-Security-Backup-and-Deployment.md`：

- 不使用 Django development server 作为生产服务。
- 使用项目批准且锁定的 WSGI/ASGI 服务与 LAN 反向代理/服务管理方式。
- SECRET、数据库凭据和环境配置位于仓库外，权限最小化。
- `DEBUG=False`、ALLOWED_HOSTS、CSRF、安全会话和错误页正确。
- collectstatic/静态资源本地化，运行时不依赖公共 CDN。
- 附件通过授权下载 View 或批准的受保护机制，不直接暴露媒体目录。
- 启动、停止、重启、迁移、健康检查、日志位置和故障排查有可执行说明。
- 不打开公网访问，不实现外网匿名 QR。

部署流程必须明确迁移前备份、迁移执行人、失败停止和恢复步骤。不得在应用启动时由每个 Web worker 竞争自动迁移。

## 权限与安全审计

对 `docs/07-Permissions-and-Workflows.md` 每个角色执行：

- 页面/菜单可见性
- 列表数据范围
- 详情对象权限
- 新增/编辑/状态动作
- 财务字段查看与修改
- 导入、导出、附件、备份下载
- 直接 URL、POST ID、HTMX/JSON endpoint 和 Service 调用

重点验证：

- IDOR/跨部门访问。
- finance-only 字段在 HTML、JSON、Excel、日志、错误信息和缓存中均不泄露。
- 停用用户、会话失效、登录失败限速/防护采用项目批准方案。
- 上传扩展名、MIME、大小、文件名和存储路径。
- spreadsheet formula injection。
- QR Token 不进入日志且撤销有效。
- 审计日志普通用户不可改删；敏感值已脱敏。
- 生产配置无硬编码 Secret/默认弱密码。

发现高风险越权、公开附件、明文 Secret 或财务泄露时必须阻止上线。

## 备份、保留与下载

按安全部署文档实现可人工运行和可计划调度的命令/脚本说明：

- PostgreSQL 一致性备份。
- 附件目录/对象存储备份。
- 数据库与附件使用同一备份批次标识和生成时间。
- 备份结果校验、失败退出码、日志和失败告警落地方式。
- 最近 30 天日备份保留；删除只针对验证过的备份根目录和明确批次。
- 不把备份写入 Web 可公开目录或 Git。
- 备份文件访问最小权限，敏感数据保护按文档执行。

管理员手动下载：

- 只对文档批准角色开放。
- 每次请求重新验证权限，不提供永久公开 URL。
- 记录下载人、时间、备份批次、文件摘要和结果。
- 不允许通过路径参数下载任意服务器文件。
- 大文件失败/中断不会标记为成功下载。

## 恢复演练

必须在隔离环境实际完成：

1. 选择一个数据库+附件同批次备份。
2. 建立空的恢复环境。
3. 恢复 PostgreSQL。
4. 恢复附件。
5. 校验迁移版本、记录数量、关键金额合计和文件摘要。
6. 登录并完成抽样资产、折旧、二维码、盘点、附件和报表检查。
7. 记录开始/结束时间、RTO/RPO 实测、问题和结论。

只写恢复文档而未实际演练，不能通过 Sprint 12。

## 性能与容量

使用可重复生成的非生产基准数据，至少覆盖 5,000 项资产及文档批准的相关历史量级，验证：

- 登录后 Dashboard
- 资产总账搜索/筛选/分页
- 资产详情
- 财务月度计提/报表
- A4 标签批次
- 盘点任务快照创建与扫码

阈值、并发模型和测试环境以 `docs/12-UAT-Acceptance.md` 为准。记录查询数、响应时间和资源指标；修复 N+1、缺索引和无界查询。不得用隐藏数据或关闭权限检查换性能。

## 事务、迁移与发布一致性

- 生产迁移按已批准顺序由单一发布步骤执行，不由多个 Web worker 并发触发。
- 迁移前完成可验证备份；迁移失败立即停止发布，不继续启动不兼容应用版本。
- 需要数据回填的迁移分批、可观测并保持既有正式数据和历史编号；禁止整表无界更新造成不可控停机。
- 应用版本、数据库迁移版本、静态资源版本和恢复说明作为一个发布单元记录。
- 备份元数据只有在数据库与附件均成功且摘要校验通过后才标记 completed。
- 管理员下载状态和 AuditLog 在授权检查后提交；失败/中断不得伪记成功。
- UAT 修复涉及关键业务事务时，必须重新执行该业务的原子性、并发和回归测试。

## UAT

逐项执行 `docs/12-UAT-Acceptance.md`，至少覆盖：

- 初始化和权限
- 新资产草稿、财务确认、正式编号、打印/确认贴标
- 六种折旧方法、旧资产承接、计提/冲销/调整
- 调拨、责任人/位置变化、借出/归还
- 部门盘点、财务全盘、位置/责任人异常、盘盈/盘亏

- 报废/出售/处置快照
- Excel 和 T+ 人工对账导出
- 备份和恢复

每项记录测试数据、步骤、预期、实际、证据、执行人和结果。失败项必须修复并回归，不能以“已知限制”掩盖必需验收失败。

- 新业务模块或 V2 维修能力

## 上线门槛与停止条件

只有以下全部成立才可建议上线：

- `docs/10-Definition-of-Done.md` 全部满足。
- `docs/12-UAT-Acceptance.md` 的全部 UAT 场景通过并有证据。
- 无已知高风险越权、财务泄露、公开附件或明文 Secret。
- PostgreSQL 迁移、备份、30 天保留和隔离恢复演练成功。
- 关键浏览器、手机、A4 打印和性能阈值通过。
- 部署、运维、恢复和回滚说明可由非开发者按步骤执行。

Completion Report 额外包含：

- UAT 结果汇总和证据位置
- 安全/权限审计结论
- 性能测试环境和结果
- 备份恢复实测时间与校验
- 上线或暂不上线建议及阻断项

如任一门槛失败，结论必须是“暂不上线”，说明修复项并停止。无论结论如何，Sprint 12 汇报后都不得自行执行真实生产部署或迁移真实数据，等待人工授权。
