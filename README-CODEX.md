## 开始一个任务

1. 以用户当前要解决的问题为目标；查看工作树、当前分支和已有修改。
2. 检查相关模块的代码、测试和迁移，再按需读取设计参考。
3. 在现有授权内自主完成必要改进，验证效果并更新实际变动的说明。
4. 交付时简述改动、验证及尚需决定的事项。纯文档任务不要求重跑全部业务测试。

## 如何理解旧需求

- 早期业务要求由 AI 生成，文中“已批准”不等于用户逐条确认。设计稿中的流程、字段和技术实现可讨论、可优化。
- 用户明确确认的业务目标优先；已有数据、金额正确性、权限和历史关联需要保护。
- `tasks/Sprint-*.md` 保存历史阶段要求，不能仅因文件存在就启动任务。用户指定 Sprint 时才将其作为该次范围参考，并核对后续修订。
- 不因普通文档差异中断整个任务。会改变金额口径、业务含义、访问权限或不可逆数据状态且当前授权不足时，说明具体影响，再确定口径。
- 历史测试结果只证明当时的运行，不能作为当前代码已通过的声明。
